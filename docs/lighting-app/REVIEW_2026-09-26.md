## 1. What changes the plan

Five findings matter more than the rest:

1. **The override wasn't guaranteed.**
   - Once the daily write cap was used up, or another DDC app was running, `light critical on` printed "ON" and exited successfully, while the monitor stayed warm.
   - Your brief makes the override non-negotiable, so this was the most serious bug.
   - *Now:* a reserved allowance for writes back to neutral (`OVERRIDE_RESERVE`, 10 per channel per day, on top of the cap). Failure is reported, never hidden. The override is restored at launch before any sensor data arrives.
2. **The tests deleted your hardware data.**
   - `run_tests.sh` ran `rm -rf probe/results`, the folder where the probes save real measurements, and HANDOFF told the Mac session to run the tests.
   - No agent flagged this directly; I found it while checking the test-audit report.
3. **Probe 05 would have failed the same way twice.**
   - Aborting by clicking the white screen left the probe measuring the desktop, which is exactly how the first run failed.
   - Its headroom check also reported false positives at realistic sensor noise. At 3% noise, up to 3 of 3 channels claimed headroom that didn't exist.
4. **The DDC transport recommendation lacked its key citation.**
   - The claim was that m1ddc's 0xB7 path fixes M1 built-in HDMI, but nothing I read says which chip sits behind those ports.
   - That makes Q9 (Mac generation, port, `m1ddc display list detailed`) the first thing to settle before any Swift DDC work.
5. **The EEPROM budget was 2× optimistic.**
   - m1ddc sends every write twice, which the budget didn't count.
   - At the brightness cap that's ~0.7 years to the assumed endurance, not 1.4, until probe 04 shows single writes land.
   - The caps still hold, and realistic use is far below them. But probe 04's result now matters more.

## 3. Decisions that are yours

1. **Darkening speed.** A ×10 drop in room light takes ~210 s to reach the target (15 s firmware average + ~135 s filter + up to 60 s write interval). Options:
   - accept a slower target for darkening (≤ 240 s);
   - or shorten `TAU_DOWN` (45 s → ~15 s gives ~120 s), at the cost of more brightness writes on flickery evenings.
   - My recommendation: accept it. Slow dimming is the comfortable direction, and it keeps writes down.
2. **Sensor gain for probe 05.** Leave `gain: auto` (verdict safe, table a few % off), or reflash with a fixed gain for the probe.
   - My recommendation: run probe 05 as is first. Reflash only if the corrected table looks off by eye.
3. **Weekly hours (Q15).** Still the biggest unknown in the build plan.
